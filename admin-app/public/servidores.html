Webs y copias automáticas

Estado en directo de cada servidor. La copia diaria se hace a las 05:00 (hora de España) en cada servidor: 35 diarias y 12 mensuales en /var/backups/copias-web/<web>/. Desactivar una copia no borra las ya hechas.

Consultando los servidores…

Despliegue

GitHub Actions en las cinco webs.

  • Cada push a main publica en «majosoft». La rama produccion también publica, pero ya no hace falta.
  • Antes de publicar se comprueba (sintaxis, pruebas de fichaje o compilación). Si algo falla, no se publica y la web sigue con la versión anterior.
  • Para subir un commit sin publicar: añadir [skip ci] al mensaje.
  • El estado de cada publicación se ve en la pestaña Actions del repo en GitHub.

Copias: cómo funcionan

Script copias-web, igual en los tres servidores.

  • Cada web es un fichero en /etc/copias-web/webs/<web>.conf (nombre, URL, GitHub, base de datos y carpeta).
  • Activa si existe /etc/copias-web/activas/<web>; el interruptor de arriba lo crea o lo borra.
  • Fichaje usa su propio script (guarda 5 años, por el registro de jornada) en /var/backups/fichaje.
  • El panel entra en los otros servidores con una clave que solo puede consultar, activar o desactivar.

Pendiente Las copias están en el mismo servidor que la web; falta sacarlas fuera.

Ver el registro

ssh <servidor> 'tail -20 /var/log/copias-web.log'

Lanzar una copia a mano

ssh <servidor> copias-web ejecutar <web>

Restaurar

Siempre sobre una copia concreta; hacer antes otra copia del estado actual.

web-playa

systemctl stop duna-carraca
runuser -u postgres -- pg_restore --clean -d duna_carraca \
  /var/backups/copias-web/duna-carraca/diarias/duna-carraca-bd-AAAA-MM-DD.dump
systemctl start duna-carraca

bambinasigns

zcat /var/backups/copias-web/bambinasigns/diarias/bambinasigns-bd-AAAA-MM-DD.sql.gz | mariadb bambinasigns
tar -xzf /var/backups/copias-web/bambinasigns/diarias/bambinasigns-ficheros-AAAA-MM-DD.tar.gz -C /var/www/bambinasigns.es

Añadir una web nueva

Webs que no son de bomberos van a «majosoft».

  1. Subir el código a /var/www/<web>.
  2. Crear /etc/nginx/sites-available/<web> y enlazarlo en sites-enabled.
  3. nginx -t && systemctl reload nginx.
  4. Apuntar el DNS (registro A) a 31.70.154.16.
  5. certbot --nginx -d <dominio>.
  6. Copiar el workflow de despliegue de otra web (.github/workflows/) para que publique con cada push a main.
  7. Crear su /etc/copias-web/webs/<web>.conf (copiar el de otra web) y activarla desde esta página.
  8. Apuntarla en esta página.
